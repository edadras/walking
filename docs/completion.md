# تکمیل — تصویر کالاها و رفع بخش‌های ناقص

پس از Phase 9 کل اپ با Spec و API مقایسه شد. هر Endpoint سرور که اپ صدا نمی‌زد و هر کد نیمه‌کاره پیدا و کامل شد.

## خروجی

| بخش | قبل | حالا |
|------|------|------|
| تصویر کالا | زیرساخت بود ولی هیچ کالایی تصویر نداشت؛ اپ فقط آیکن نشان می‌داد | ۸ تصویر برای کالاهای نمایشی (`database/seeders/assets/products/{slug}-{n}.jpg`)، گالری ورق‌خور با نشانگر صفحه و انیمیشن Hero، تصویر کوچک در فهرست و جزئیات سفارش، Cache دیسکی (`cached_network_image`) |
| آپلود تصویر در ادمین | فایل خام با هر ابعادی | فقط JPEG/PNG/WebP، برش ۶:۵ و کوچک‌سازی تا ۱۲۰۰×۱۰۰۰ در مرورگر، ستون تصویر در فهرست کالاها، حذف فایل از دیسک با حذف یا جایگزینی رکورد |
| آواتار | API داشت، اپ صفحه‌ای برایش نداشت | انتخاب از گالری یا دوربین (با PermissionPrimer)، حذف عکس، `DELETE /me/avatar` |
| Push | ارسال FCM در سرور بود، ولی اپ هیچ‌وقت Token نمی‌فرستاد | `firebase_messaging`، ثبت Token با `PUT /devices/push-token` (فقط وقتی عوض شود)، نمایش Push در حالت باز بودن اپ، باز شدن صفحه مرتبط با لمس Push در هر حالت (باز، پس‌زمینه، بسته) |
| تحلیل محصول | Endpoint `analytics/events` بود ولی هیچ رویدادی ارسال نمی‌شد | صف دسته‌ای در اپ: `app_open`، `onboarding_completed`، `permission_prompt/result`، `walking_started/completed`، `challenge_joined`، `coupon_claimed`، `store_view`، `product_view`، `purchase`، `sponsor_visit` |
| گزارش خطا | `main.dart` فقط «Phase 9: forward to crash reporting» داشت | `POST /client-errors` با گروه‌بندی بر اساس Fingerprint و صفحه «خطاهای اپ» در ادمین (با Badge و دکمه «رفع شد») |
| کد مرده | `ComingNextPage` و رشته‌های «به‌زودی» | حذف شد |

## حریم خصوصی و امنیت

- **تصویر آواتار روی سرور دوباره Encode می‌شود** (`ImageSanitizer`): برش مربعی، حداکثر ۵۱۲ پیکسل، JPEG تازه. با این کار EXIF و مختصات GPS دوربین هم حذف می‌شود. این با اصل «حداقل داده مکانی» هم‌خوان است. نام فایل ULID دارد تا دو آپلود هم‌زمان فایل یکدیگر را پاک نکنند (این باگ را تست پیدا کرد).
- **گزارش خطا عمومی است**، چون کرش قبل از ورود هم رخ می‌دهد. برای همین:
  - محدودیت نرخ: ۱۰ در دقیقه و ۳۰۰ در روز برای هر IP.
  - تکرار یک خطا فقط شمارنده را زیاد می‌کند.
  - متن در سرور پاک‌سازی می‌شود: شماره موبایل، ایمیل، Token و عددهای بلند حذف می‌شوند.
  - اپ هم فقط ۴۰ خط بالای Stack و حداکثر ۲۰ گزارش در هر اجرا می‌فرستد.
  - گروه‌هایی که ۹۰ روز تکرار نشده‌اند با `retention:prune` حذف می‌شوند.
- **رویدادهای تحلیلی قبل از ورود** (مثل Onboarding) در صف می‌مانند و بعد از ورود ارسال می‌شوند. با خروج کاربر، صف پاک می‌شود تا رویدادی به حساب بعدی نسبت داده نشود. Whitelist نام‌ها و حذف کلیدهای شخصی در سرور بدون تغییر ماند.
- **Push:**
  - داده Push فقط نوع و شناسه دارد. اپ مسیر را از روی نوع می‌سازد (`notificationRoute`)، پس Push نمی‌تواند اپ را به مسیر دلخواه ببرد.
  - پیکربندی Firebase با `--dart-define` داده می‌شود و `google-services.json` در مخزن نیست.
  - بدون این پیکربندی Push غیرفعال است و صندوق اعلان داخل اپ کار می‌کند.
- Image در Docker حالا افزونه `gd` (JPEG/WebP) را دارد.

## تست‌ها

- **Backend (۲۰۸):**
  - ترتیب و URL تصاویر کالا، و حذف فایل با جایگزینی یا حذف رکورد.
  - آواتار: Encode دوباره به JPEG مربعی، حذف فایل قبلی، رد فایل غیرتصویری.
  - گزارش خطا:
    - گروه‌بندی، پاک‌سازی داده شخصی، و باز شدن دوباره خطای «رفع‌شده» وقتی تکرار شود.
    - ثبت کاربر، اعتبارسنجی ورودی و Throttle.
    - دسترسی نقش‌ها و Prune.
- **Flutter (۹۱ + ۲ تست اسکرین‌شات):**
  - آواتار: گالری، انصراف و حذف.
  - Push:
    - ثبت Token فقط یک بار و ثبت دوباره فقط با Token تازه.
    - باز شدن صفحه سفارش با لمس، نمایش Push در حالت باز بودن اپ، و Build بدون پیکربندی.
  - نگاشت نوع اعلان به مسیر.
  - Analytics:
    - صف قبل از ورود و دسته‌بندی ارسال.
    - نگه داشتن رویدادها وقتی ارسال شکست بخورد، پاک شدن صف با خروج، و سقف صف.
  - CrashReporter: حذف تکراری‌ها، سقف گزارش، و اینکه خودش هرگز Exception نمی‌دهد.
  - گالری کالا.
